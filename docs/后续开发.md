# 后续开发

记录已经讨论过、暂时不做的功能。动手前先和需求方确认一遍，细节可能已经变了。

## 1. 更多 Markdown 语法的显示支持

### 现状

程序目前只识别以下几种写法，其余 Markdown 语法原样保留在文件里（不会被改动或破坏），界面上当普通文字显示：

| 写法 | 作用 |
|---|---|
| `- [ ]` / `- [x]`（`*`、`+` 开头也行） | 一条素材 / 已完成 |
| `#标签`、`#父/子` | 标签、层级标签 |
| 任务行下缩进的文字、缩进的普通列表 | 属于这一条（续行） |
| 缩进的 `- [ ]` | 独立的一条 |
| `^abc123` | 条目编号 |
| `%%备注%%` | 复制时跳过，灰色 |
| `==标记==` | 「部分复制」只取这些，黄色底色 |
| `http(s)://…`、`www.…` | 链接，可打开 |
| `# 标题` | 只在「阅读原文」里放大；不是素材 |

当普通文字显示的：`**加粗**`、`*斜体*`、`~~删除线~~`、`` `行内代码` ``、`[文字](网址)` 的 `[文字]` 部分、`> 引用`、```` ``` ```` 代码块、`---` 分隔线、`1.` 有序列表、表格、`![图片](…)`、`[[双链]]`、脚注。

### 计划（三项可以分开做）

**A. 常用行内格式**

- 范围：`**加粗**`、`*斜体*`、`~~删除线~~`、`` `行内代码` ``。
- 卡片、阅读原文：显示效果并隐藏符号。
  - 加粗：现在只有一个中文字体（微软雅黑常规体），没有粗体字形。可以用加深颜色或描边模拟，或者额外加载粗体字体文件（会增加内存，要权衡）。
  - 斜体：egui 不支持字体倾斜，需要找替代表现（比如换颜色），或者干脆不做。
  - 删除线：`TextFormat::strikethrough`，直接可用。
  - 行内代码：等宽字体 + 浅灰底色（`TextFormat::background`）。
- 编辑原文：保留符号，只上色（沿用 `highlight_markdown` 里 `restyle` 的做法）。
- 复制全部 / 部分复制：要决定是否去掉这些符号。建议去掉，复制出来的是纯文字。
- 注意：`*` 和 `_` 容易误判，比如乘号、文件名里的下划线。只在成对且紧贴文字时才算。

**B. `[文字](网址)` 只显示文字**

- 卡片、阅读原文：只显示「文字」，做成链接样式；Ctrl+单击（卡片）/ 单击（阅读原文）打开网址；悬停时提示完整网址。
- 右键「打开链接 / 复制链接」：列出这种链接，显示文字，打开网址。
- 复制全部：只复制文字，还是「文字（网址）」，还是保持原样？待定，做之前问需求方。
- 现有 `find_urls` 已经能从 `[文字](https://…)` 里识别出网址（会去掉不配对的右括号），可以在它的基础上扩展。

**C. 阅读原文里的块级格式**

- `> 引用`：左侧画一条竖线，文字缩进、变淡。
- 代码块 ```` ``` ````：等宽字体 + 浅灰底色整块；块里的内容不做标签、备注、网址等识别。
- `---`：画一条水平分隔线。
- `1. 有序列表`：保持编号，统一缩进。
- 阅读原文目前是一个 `LayoutJob` 交给一个 `Label` 显示（`render_reading`）。竖线、分隔线、整块底色这类效果，一个文本布局画不出来，要改成按块分段显示，或者在排好的文字上叠加绘制。

**不建议做**：表格、图片显示。实现复杂，图片还要解码、占内存，和轻量化的目标冲突。

### 已知问题：代码块放在素材里会丢空行

- 顶格写的 ```` ``` ```` 不属于任何素材，会打断上面那条素材的续行。
- 代码块整体缩进写到任务行下面，可以成为续行，但读取时 `clean_text` 会去掉续行里的空行，代码里的空行会丢失。
- 如果要支持「素材里放代码块」，需要在解析时识别缩进的 ```` ``` ```` 区间，区间内保留空行和原样缩进。还要检查 `to_line` 写回时不会破坏这一段。

### 开销要求

- 只在显示时处理，结果和现有着色一样按「文字 + 样式」缓存（`FrameCache`），文字不变就不重新计算。
- 卡片只处理屏幕上能看到的那些（虚拟滚动），条目多也不卡。
- 空闲时 CPU 仍然为 0。
- 改完跑一下容量测试：`cargo test --release capacity -- --ignored --nocapture`，和改动前对比每帧耗时。

## 2. 独立的卸载程序（双击卸载）

### 现状

一键卸载目前在程序里：「设置 → 卸载素卡…」（`src/uninstall.rs` + `App::uninstall_dialog`）。
需求方希望像常见软件一样，在程序旁边有一个单独的「卸载」图标，双击就弹出卸载确认，不用先打开素卡。

### 共同的前提

程序加一个「只做卸载」的启动方式：不打开主界面，只显示一个小窗口，内容就是现在的卸载确认框
（列出要删的文件，勾选「同时删除我的数据（移到回收站）」，默认不勾）。确认后删除方式不变。
删除列表要把卸载用的文件本身也加进去。

### 方案

**A. 下载包里附带「卸载素卡.exe」（推荐）**

- 就是 `sucard.exe` 的副本改了名字；启动时看自己的文件名，叫「卸载素卡」（macOS / Linux：`uninstall-sucard`）就进入只做卸载的模式。
- 双击直接弹出卸载窗口，没有命令行或终端窗口；Windows 上可以嵌一个专门的图标（比如叠卡加红色减号）。
- 三个平台都可用。代价：下载包里有两份程序，压缩后约从 2 MB 变成 4 MB。
- 要改：按文件名判断模式（几十行）、卸载用的小窗口、`.github/workflows/release.yml` 打包时复制一份并改名，以及卸载图标。

**B. 单独写一个很小的卸载程序**

- 不用界面库，只用系统对话框，几百 KB。
- 三个平台要各写一套；系统对话框只能“是 / 否”，没法显示文件列表和勾选项，删不删数据要再问一次。代码多、体验差。

**C. 附带卸载脚本**

- 脚本用 `--uninstall` 参数启动同目录的 `sucard`，进入只做卸载的模式。几乎不增加体积。
- Windows `卸载素卡.cmd`：能双击，会闪一下黑色命令行窗口。
- macOS `卸载素卡.command`：双击会先打开“终端”；下载来的脚本同样会被 Gatekeeper 拦截，要先放行。
- Linux `uninstall-sucard.sh`：双击能不能运行取决于桌面环境，可能被当成文本打开，或要先设置可执行。
- 图标都是系统默认的脚本图标，不能换。

需求方暂不改，倾向在 A 和 C 之间选：在意 Windows 体验选 A，在意下载包大小选 C。

## 3. 标签面板的输入框加上右键菜单

### 现状

v0.1.10 起，快速添加、搜索、新建文档、修改标题这几个输入框右键有撤销、重做、剪切、复制、粘贴、全选（`input_with_menu`）。
标签面板（快速添加左边的「# 标签 ▼」、卡片右键「编辑标签…」）里的「筛选，或回车新建」输入框还没有，只能用 Ctrl+C / V / X / A。

### 为什么没直接加

标签面板本身就在弹出菜单里，egui 0.31 的菜单不能嵌套（试过，测试 `tag_panel_input_context_menu` 没通过）：

- 「# 标签 ▼」是 `menu_button`：在菜单区域外按下鼠标就关闭（`MenuRoot::stationary_interaction`），点右键菜单里的项会把整个标签面板关掉，菜单项的操作也执行不到。
- 「编辑标签…」在卡片的右键菜单里：egui 全局只有一个右键菜单（`CONTEXT_MENU_ID_STR`），在里面再开一个右键菜单会把卡片菜单替换掉。

### 可能的做法

- 不用 egui 的 `context_menu`，自己画一个小弹层：右键时记下位置，用 `egui::Area`（`Order::Foreground`）画菜单项。
  还要让外层菜单不因为点到小弹层而关闭——外层用的是 egui 自带的菜单，关不关由它决定，可能要把标签面板也改成自己画的弹层。
- 或者等 egui 升级：新版本重写了菜单和弹层，可能可以嵌套（没验证），升级后先直接试 `input_with_menu`。
- 不管哪种，都要保证用完右键菜单后标签面板还开着、输入框拿回焦点；把上面那个测试补回来。
